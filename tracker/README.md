# tracker

One file per upstream SIEM rule set, recording every rule and what was done with it.
All three are generated — rerun the tool, never hand-edit.

| Tracker | Upstream | Generated by | What it records |
|---|---|---|---|
| [splunk_tracker.md](splunk_tracker.md) | [Splunk security content](https://research.splunk.com/detections/) | `python3 tools/track_sources.py` | every rule with its routing decision (`convert`, `covered`, `blocked-telemetry`, …) |
| [elk_tracker.md](elk_tracker.md) | [Elastic detection rules](https://elastic.github.io/detection-rules-explorer/) | `python3 tools/track_sources.py` | the same, for Elastic |
| [sigma_tracker.md](sigma_tracker.md) | [SigmaHQ `rules-threat-hunting/windows`](https://github.com/SigmaHQ/sigma/tree/master/rules-threat-hunting/windows) | `python3 tools/import_sigma.py` | every stored Sigma rule — Category, TTP, Rule, Description, Path |

Splunk and Elastic rules are triaged, not stored. Sigma rules are stored unmodified under
`hunt/<category>/sigma/`. Rules with no ATT&CK mapping are listed in
[`unclassified-threat-check/`](../unclassified-threat-check/). How triage decides is in
[CLAUDE.md](../CLAUDE.md#upstream-rule-ingestion).
