# tracker

One file per upstream SIEM rule set, recording every rule and what was done with it.
All three are generated by `python3 tools/track_sources.py` — rerun it, never hand-edit.

| Tracker | Upstream | What it records |
|---|---|---|
| [splunk_tracker.md](splunk_tracker.md) | [Splunk security content](https://research.splunk.com/detections/) | every rule with its routing decision (`convert`, `covered`, `blocked-telemetry`, …) |
| [elk_tracker.md](elk_tracker.md) | [Elastic detection rules](https://elastic.github.io/detection-rules-explorer/) | the same, for Elastic |
| [sigma_tracker.md](sigma_tracker.md) | [SigmaHQ `rules-threat-hunting/windows`](https://github.com/SigmaHQ/sigma/tree/master/rules-threat-hunting/windows), one pinned commit | the same, for Sigma, plus `blocked-logsource` for rules whose own log source this sensor lacks |

No upstream rule is stored in this repository. A rule counts as converted when a template
cites its raw URL in `info.references`. Rules with no ATT&CK mapping are listed in
[`unclassified-threat-check/`](../unclassified-threat-check/). How triage decides is in
[AGENTS.md](../AGENTS.md#upstream-rule-ingestion).
