# hunt/HEARTH

Hunt templates converted from the community hypotheses in
[THORCollective/HEARTH `Flames/`](https://github.com/THORCollective/HEARTH/tree/main/Flames),
one template per hypothesis file.

```
hunt/HEARTH/H<nnn>-<behaviour>.yaml
```

Read against upstream commit `59e1671457cab630adaf87388f9a2910b6769540`. Each template
cites its source file in `info.references`.

## What a conversion is

A HEARTH file is a sentence, a few reasons and some links. It carries no query. The
template is authored from it: the hypothesis is kept as upstream states it, and the
evidence, risk logic, verdict and CQL are written here against CrowdStrike event names.

Rules these templates follow:

| Rule | Why |
|---|---|
| CQL only, `crowdstrike-ngsiem` the only connector | No Wazuh block is carried in this tree. |
| No `groupBy`, no `sort()`, no `select()`, no join | Every case returns raw events. Where the hypothesis is about succession or breadth, the evidence item says the agent derives the count from the returned events. |
| Built to run over long windows | Each case opens on one exact `#event_simpleName` tag, applies the cheapest and most selective test next (platform, image name, port, CIDR), and reaches for an unanchored command-line regex last. `SyntheticProcessRollup2` is not read. Event streams too large to return raw over months, such as every SMB connection on port 445, are narrowed by name or left out, and the case's `purpose` says so. |
| MITRE ids come from `tools/attack_extract.py` | Same as invariant 1 in [AGENTS.md](../../AGENTS.md#hard-invariants). Tactics, detection strategies, analytics and data components were read from the STIX bundle, not copied from the HEARTH front matter. |
| A hypothesis the sensor cannot observe is not converted | Same as invariant 5. It is listed below with the reason. |

## Why it is outside the validated corpus

The folder is keyed by HEARTH's hypothesis number, not by category and technique, so no
file here can satisfy L5's `hunt/<category>/<Txxxx-slug>/` layout. Several hypotheses are
also pitched wider than this corpus allows: H006 covers RDP, SMB and SSH in one file and
H007 covers three interpreters, where invariant 4 would make each a file of its own.

The templates are still written to pass L1–L4. Check them by passing the paths:

```bash
python3 tools/validate.py hunt/HEARTH/*.yaml
```

Expect exactly one L5 layout error per file and nothing else, apart from the L2 "decomposes
into sub-techniques" error on a file listed below as kept at its parent technique.

`validate.py`, `coverage.py` and `add_wazuh_block.py` prune this folder the way they prune
`hunt/keyword/`, so `tools/validate.py --strict` with no path does not walk it and nothing
here counts toward coverage. Passing the paths, as above, is the only way these files are
checked.

Most of these behaviours already have a template under a category folder. The ledger names
it, so the two can be compared and the better case moved across.
